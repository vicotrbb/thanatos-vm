# Thanatos v1 Implementation Plan

> **For agentic workers:** executed inline (the user asked for one sequential run). Steps use checkboxes.

**Goal:** DESIGN.md section 10, steps 1-9, ending in a `v1.0.0` tag.
**Architecture:** see DESIGN.md section 4. One process, one VM, threads and blocking I/O.
**Tech Stack:** Rust stable; only the crates in DESIGN.md section 11.
**Spec:** `DESIGN.md`.

## Global Constraints
- Gates: `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`, via `just check`.
- `unsafe` only in `thanatos-hv`, each block naming its invariant. Guest memory only through `vm-memory`.
- Dependencies only from section 11. No `whp`, no stub. No emulation fallback. No feature flags but `window`.
- A step is done when its test passes on available hardware, `just check` is green, and it is committed.
- This machine has HVF only. KVM paths are compile-checked here and proven by CI; the commit says so.

## Review Focus
1. A guest reaching host loopback through the user-mode network: refused unless explicitly allowed.
2. Malformed virtqueue chains and register writes: never panic the VMM (fuzz targets, unit tests).
3. A missing kernel or disk: an error naming the path, not a panic.
4. A stale API socket from a killed VM: `run` replaces it; a live one is refused.
5. A short or oversized agent frame, or RFB client message: the connection closes, the VM keeps running.
